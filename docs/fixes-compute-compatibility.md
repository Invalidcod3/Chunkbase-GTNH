# 计算调度与兼容性修复

对应 `audit-compute-compatibility-2026-09-15.md` 的 C1～C3。生产改动仅涉及线程池、线程客户端的就绪选项、GPU 初始化调度和状态说明；没有改动生成算法、群系配色、缓存键或缓存容量。

## 已完成

- **C1：失败恢复。** 所有线程均失败时，地图重试会重建主线程，然后重试函数包和地图。重建失败明确报错。主线程等待真实函数包就绪，不套用辅助线程的 15 秒扩张超时；辅助线程的超时、失败降档和迟到消息隔离保留。
- **C2：初始化等待。** 支持 GPU 的首次查询触发后台初始化，当次及初始化期间的查询走 CPU。设备自检通过后，后续查询才使用 GPU。首条真实 GPU 查询的 CPU 对照保留；切换档位后，旧初始化不能继续向新设备派发自检。
- **C3：首批调度。** 待执行任务保留在线程池中，每个就绪线程一次领取一个任务。线程就绪、任务完成均触发调度；主线程可以处理辅助线程启动期间的排队工作。队列保留优先级，并覆盖取消、世界切换、降低并行度和线程失败重试。
- **扩张成本判断。** 记录实际启动耗时及各维度、查询类型的近期耗时。已知短批次预计能由现有线程提前完成时，暂缓扩张；未知工作允许逐步尝试，昂贵积压仍能增加线程。不通过重置健康线程或清空缓存来调整负载。

## 验证

- 492 项 Node 测试通过；新增恢复、冷启动分流、优先级、队列取消、主线程就绪、后台 GPU 初始化、旧设备隔离及扩张成本判断覆盖。
- 真实独立 8 Worker：6 个维度，9 个查询，2,907 个像素，与单线程 provider 对照一致。
- 实际暮色函数包：三轮，每轮分别设置 1、4、8 个目标线程，执行两批 8 个 64×64 查询。144 次查询、589,824 个输出像素相互一致。
- 保存的原实例结构数据重放：916 个结构匹配。
- 保存的原实例刷怪笼数据重放：99 个候选匹配，检查 2,293,760 个洞穴单元。
- 完整预览验证：42 个群系底图、41 个资源维度、24 个固定群系维度，原结构路由保留。

## 保留的边界

本轮没有进行浏览器交互、实际 GPU 驱动性能测试、64 线程内存压测或在线更新混用版本复现。扩张成本判断不等于整机负载、实时可用内存或浏览器帧率反馈。GPU 设备仍按 Worker 隔离，跨线程共享 GPU 队列和不可变构建版本握手仍是后续开发项。
