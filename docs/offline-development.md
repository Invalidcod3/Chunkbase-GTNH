# 离线开发记录

按用户要求先离线开发，之后再启动实例校准。本轮没有启动 GTNH、修改实例配置或读取存档。

## 已完成

- RWG 村庄：保留实际 ChunkManager 的原始地形适宜性检查字节码，使用原 Worker 的区域候选规则；接入私有本地预览的 structures 能力。24 组查询、344 个候选点与原 Java 一致。判定使用原始 rNoise 高度及邻域起伏，不能换成最终混合底图高度。
- 模组结构：LootGames、Tinkers 空岛、AE2 陨石、Automagy 尖塔，按指定实例的磁盘配置计算；Nether fortress 使用参考桌面的原生下界坐标及 +11 标记偏移。72 组 Java 参考样本覆盖正负坐标、世界边界附近、long 极值、超过 2^53 的种子、两组配置，并验证查询拆分不会漏点或重复。
- 图标沿用参考项目；新标记支持原有筛选、详情、坐标跳转和三种结构导出。
- 矿脉／流体模式、资源结果校验、绘制、搜索、产量阈值、详情及 CSV／JSON／JourneyMap 导出接口已接通。没有真实资源函数包时显示待接入；目前不能实际预测矿脉或流体。
- 只读采集工具支持维度、命名空间、结构组、资源目录和资源查询。批量采集保留已完成结果，任何失败都保持 `complete:false`。存档记录及当前流体数据不能混作纯种子校准样本。
- RWG 编译后重新运行原 JVM 地形及已保存的 Worker 样本：96,000 个群系像素、3,840 个 JVM 群系与 3,840 个 binary32 高度一致；网页稀疏采样另有 1,024 像素一致。村庄和地形报告均绑定函数哈希，构建拒绝过期报告；校准不一致时命令返回失败。

## 后续校准

2026-09-14 本地验证：354 项 Node 测试、13 项 Python 工具测试全部通过。浏览器已检查主世界新增结构、下界结构、资源未接入提示，以及下界／流体模式切回末地后的底图与标记；未进行真实资源图层视觉验收。默认静态包约 200 KiB，另有包含本地 RWG 函数的私有 ZIP。

在实例可用时执行以下只读采集，不需要改动网页运行方式：

```sh
python tools/collect-calibration.py --instance "PATH_TO_INSTANCE" --plan tools/calibration-plan.json --output private-packs/runtime-session/remaining-reference.json
```

采集计划内的维度 ID 和种子可调整。若该种子与当前已载入存档相同而返回记录，必须换用其他种子；不要通过删除来源字段绕过检查。目录和查询样本不能替代资源生成器初始化状态，需要额外捕获每个维度的候选顺序、矿脉权重、矿脉布局配置及流体目录。

`node tools/verify-mod-reference.mjs` 可重新运行原 Java 样本；它与网页结果的比较由 `tests/mod-structures.test.mjs` 完成。村庄验证运行 `node tools/verify-rwg-villages.mjs`，需要本地私有编译产物。
