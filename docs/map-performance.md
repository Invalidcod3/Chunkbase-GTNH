# 地图渐进加载与 RWG 采样优化

最新 [地图内存管理](map-memory-management.md) 改为按视野和字节预算保留历史瓦片，并释放离屏画布及长期空闲的额外计算线程；采样精度不变。

最新 [暮色与扩展维度优化](dimension-loading-optimization.md) 已把时间预算调度和完成栅格复用用于另外 7 个多群系维度；包含配对测量、缓存隔离验证及群系注册别名修复。下文的 RWG 基线仍独立保留。

2026-09-15 复审发现的暮色预览退化、旧视野队列等问题已修复，见 [F5–F9 修复记录](fixes-f5-f9.md)。暮色现在采用有界批量生成后抽样，Worker 支持按请求取消和排队优先级。下文保留 RWG 的局部性能结果，不能推断所有维度都会获得相同比例的提升。

## 通用的粗算 → 精算

`MapView` 默认采用粗算再精算。新瓦片优先用每轴一半的采样点生成预览，再计算当前缩放级别原本要求的完整瓦片。例如，一个 128×128、间隔 4 方块的瓦片，先请求覆盖同一区域的 64×64、间隔 8 方块的预览。采样间隔最多为 256；达到上限时直接计算完整瓦片。

CPU 火焰图优化后，暮色与配置包含 GenLayer 图的扩展维度通过函数包的 `biomePreview: "direct"` 提示直接生成完整瓦片：这些生成链即使减少输出点，仍需生成近似相同的底层区域，额外预览反而重复计算。主世界等维度继续使用默认渐进流程；已有瓦片仍按原逻辑复用。测量与校准见 [CPU 优化替换记录](cpu-optimization-release.md)。

清晰度试用版把此前 32×32 的预览提高到 64×64：单轴色块宽度减半，采样点增加为 4 倍，最终精度不变。优先改善首眼观感，代价是首批预览可能比上一版稍晚。

预览来自对应维度的真实采样函数，但点与点之间暂时放大显示，细小地形可能尚未出现。页面显示“地图预览 · 正在精化”。空白区域的预览优先于已有预览的精化，同一阶段优先靠近视野中心的瓦片。最终结果仍采用原有采样精度和配色。

- PNG 检查精化状态，预览不能被当作已完成底图导出；群系 JSON 独立请求完整的导出栅格。
- 切换种子、维度或环境配置后，旧请求不能回填新地图。
- 仅切换结构、矿脉、流体模式时保留相同世界的底图，避免重复加载。
- 拖动、缩放时按世界坐标复用缓存底图。绘制时依据实际采样间隔排序，新到达的粗预览不能覆盖更细的旧瓦片；只有当前级别精算完成后才优先显示新结果。鼠标群系名称使用相同的显示顺序，尚未覆盖的新区域继续显示预览。缓存底图不会被误判为当前级别已经精化完成。
- 有效世界边界分别裁剪粗、细请求；未安装群系实现的维度不会无限精化。粗请求失败后可重试完整请求。

这是改善首批可见结果的通用策略，不保证总计算量下降。预览也有成本，尤其是大间隔采样仍需访问很多 RWG 混合区块时。

## RWG：精确计算所需采样点

旧实现即使每区块只使用 1 个或 16 个像素，也先算完该区块的 256 个最终群系。新增 `finalSamples` 入口复用原来的混合、浮点计算和地表/河流判定，只对请求坐标选择最终群系。间隔 1 的查询与结构查询继续使用原完整区块路径；间隔大于 1 的底图使用新入口。间隔 4 的原有 +2 方块采样偏移保持不变。

该捷径仅用于当前已校验的 GTNH 2.9.0-beta-3 编译配置，其中改变群系的 DuneValley 判定可按点计算。编译器继续校验允许的运行时类和地表实现哈希；未知实现不能自动套用此捷径。不能把它理解为任意 Forge 地表回调均可省略整区块执行。

Provider 另保存最多 8 MiB 的完成栅格，以最近使用顺序淘汰。返回数组与缓存分离，Worker 转移数组缓冲区不会破坏缓存；换种子清空缓存，中途取消不写缓存。保留原区块缓存，新缓存专门避免大瓦片重访时因底层区块已被淘汰而全部重算。稀疏查询每次最多调用 32 个采样点，并在计算片段间检查取消。

## 本机结果

同一种子 `0`、起点 `(1536, 0)`、128×128 像素，保存优化前的引擎及 Provider，与本次实现成对运行。以下是一次本地 Node 计算测试，不是浏览器首屏耗时或跨设备基准；不同采样间隔覆盖不同大小的世界区域。

| 采样间隔 | 优化前首次 | 优化后首次 | 加速 | 优化后重复请求 |
| --- | ---: | ---: | ---: | ---: |
| 4 方块 | 2,521.41 ms | 618.42 ms | 4.08× | 0.07 ms |
| 8 方块 | 8,874.21 ms | 946.54 ms | 9.38× | 0.11 ms |
| 16 方块 | 34,475.55 ms | 2,996.41 ms | 11.51× | 0.14 ms |

三组最终瓦片均与优化前逐像素一致。重复请求时间只包括 Provider 返回缓存，不包括 Worker 通信或绘制。

此前 32×32 预览的独立渐进计算测试测得三档预览分别约 231、471、1,092 ms，预览加精算总计约 406、934、3,926 ms。这组独立运行会受 JIT 和缓存预热影响，不能与上表直接相减；它也说明粗算能提前出图，但可能增加完成整张瓦片的总时间。可用 `node tools/benchmark-rwg-preview.mjs` 在具有当前私有编译包的本机复测当前 64×64 预览，或追加 `--coarse-factor=4` 测此前的 32×32 策略；结果带有 `previewSize`，写入 `.test-work/rwg-progressive-benchmark.json`。

## 验证范围

- 通用调度测试覆盖主世界、暮色、末地和月球的预览/精化、完成判定、优先级、模式切换、缺失实现和失败重试。
- 与保存的实例采集结果对照：完整区块入口 96,000 像素，新稀疏入口另 96,000 像素，均无差异。
- 独立 JVM 参考路径：3,840 个群系和 binary32 高度，以及 6,390 个不同间隔/偏移的稀疏像素一致。
- 地形相关回归：344 个村庄参考样本、1,079 个地表结构位置、99 个刷怪笼候选和 916 个模组结构位置通过原有校验。
- 私有打包额外校验稀疏入口报告与当前引擎、配置的哈希匹配；旧报告不能用于发布新引擎。

这些是自动化数值和调度验证。本轮没有完成真实浏览器交互验收，也没有重新启动游戏采集新样本。单 Worker 的串行计算和昂贵结构扫描仍是后续性能工作方向。

重新校准新入口时，在现有完整入口校准之外执行：

```sh
node tools/calibrate-rwg.mjs --terrain --coverage --sparse
node tools/calibrate-rwg.mjs --terrain --extra --sparse
```

完整本地包仍需静态 HTTP 服务；解压后双击 `index.html` 的 `file://` 限制不受此次计算优化影响。
