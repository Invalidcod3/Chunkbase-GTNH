# 跨系统与硬件性能检查（2026-09-15）

## 结论

当前代码存在会随浏览器、设备内存、处理器和屏幕像素密度变化的性能风险；尚不能确认 Windows、macOS、Linux、x86-64、ARM64 上都流畅。本次没有复现某个操作系统独有的卡顿，也没有修改 UI 或生产代码。

## 本次验证

- 环境：Windows x64，AMD Ryzen 7 7745HX，16 个逻辑处理器，31.18 GiB 系统内存，Node v24.19.0。
- 运行 GPU 绘图、GPU 计算、线程池、地图内存、视野调度、算力分配和 Worker 通信的 7 个测试文件：62 项通过，0 失败。GPU API 使用替身，不能据此声称真实显卡性能通过。
- 重新运行 `tools/audit-compute-compatibility.mjs --fixed`：当前线程池配合完整本地预览的实际计算引擎，通过 Node 独立线程执行暮色查询。3 轮 × 3 个目标线程数 × 2 个阶段 × 8 个查询，共 144 次查询、589,824 个输出像素，各组结果一致。
- GPU 初始化取消与唯一线程失效后的重试检查通过；这些故障采用模拟条件，不是实机资源耗尽测试。

| 目标线程数 | 冷启动整批耗时中位数 | 相同查询重复耗时中位数 | 各轮批次完成时就绪线程数 |
| --- | ---: | ---: | --- |
| 1 | 242 ms | 87 ms | 1 |

每批 8 个 64×64、step=4 查询。4 与 8 两档实际都只启用了 2 个就绪线程，不能把计时差异解释成 8 线程收益。这是计算基准，不含浏览器首屏、拖图帧率、真实 GPU 或交互延迟。

## 已确认的代码行为与待测影响

| 场景 | 代码证据 | 可能影响，尚未实机量化 |
| --- | --- | --- |
| 高 DPI / 大画布 | `dist/map.js:194` 的 resize 按完整 devicePixelRatio 设置画布，没有像素预算；GPU 绘图也使用相同物理尺寸 | 同样 CSS 视口在 DPR=2 时像素量为 DPR=1 的 4 倍，DPR=3 时为 9 倍；绘图和缓冲区负担增加 |
| 浏览器没有内存提示，用户提高并行度 | `dist/gpu-settings.js:18` 在 deviceMemory 缺失时仅受逻辑处理器与 64 线程上限约束 | 已直接调用函数验证：16 逻辑处理器、2 GiB 提示时预算为 2；4 GiB 时为 4；缺失内存提示时为 15。默认仍是 1 线程，预算不会自行把默认设置提高到 15 |
| 低内存、大视野和多个计算线程 | `dist/map-memory.js:14` 的 1～8 MiB 限额仅限制历史瓦片，当前可见瓦片受保护；各计算线程保留独立引擎及缓存 | 历史缓存上限不等于整页内存上限，仍可能遇到内存压力；未做页面堆或系统进程内存实测 |
| GPU 高档叠加多线程 | 每个 Worker 内 GPU 设备独立初始化、自检和验证首条实际查询；WebGL2 底图还需合成到主画布 | 存在重复初始化、缓冲区与合成开销。GPU 是否更快取决于设备和查询负载，当前没有按实测 GPU/CPU 收益自动选择路径 |
| 大量资源或结构标记、持续拖图 | `dist/map.js:522` 在主界面线程绘制底图、资源、网格和结构，地图变化时重绘 | 计算放入 Worker 不能消除绘图瓶颈；需要单独测拖动和缩放的帧耗时 |

例如 1920×1080 CSS 视口，按单份 RGBA8 像素估算，DPR=1 约 7.91 MiB，DPR=2 约 31.64 MiB。此数值不是浏览器真实内存或显存；未包含额外画布、双缓冲和驱动开销。

浏览器能力也不统一：[deviceMemory](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/deviceMemory) 和 [WebGPU](https://developer.mozilla.org/en-US/docs/Web/API/WebGPU_API) 的官方文档均标记为有限可用，并受安全上下文限制。项目已有能力检测、GPU 自检和 CPU 回退；回退保证有替代路径，不能保证相同速度。

## 已有保护

默认单线程、GPU 关闭；线程逐步启动并依据启动成本判断扩张，失败时限制容量；额外线程空闲 60 秒后回收；离屏瓦片画布和纹理释放；GPU 异常回退；取消旧视野请求。上述措施有助于控制开销，但没有跨设备性能合格结论。

## UI 改动前仍需的实机验收

下表全部是待测覆盖范围，本次没有远程或本地的这些浏览器/设备实测结果。

| 覆盖组 | 组合 |
| --- | --- |
| Windows | Chrome / Edge / Firefox；集成显卡与独立显卡；低内存设备与当前机器 |
| macOS | Apple Silicon 的 Safari / Chrome；若支持 Intel Mac，再增加 x86-64 设备 |
| Linux | Chrome / Firefox；至少一组实际显卡和驱动环境 |
| 手机和平板（若属于支持范围） | Android Chrome / iOS Safari，关注高 DPR 和低内存 |

统一种子、维度、视口和图层，覆盖冷启动、首块预览、精算完成、连续拖动缩放、密集资源标记、切换维度、闲置后恢复以及 PNG 导出。记录首次可见时间、完整加载时间、帧耗时 P95、超过 50 ms 的主界面长任务、进程内存峰值及空闲后走势，并分别测试 GPU 0/1/3/4 档与线程 1/2/4 档。设备提示和 CPU 限速只能辅助定位，不能冒充不同操作系统或真实低内存硬件。

建议优先补齐缺失内存提示时的保守预算、画布像素预算与真实交互测量，再依据实测结果决定是否调整默认档位。性能测量应先于外围 UI 改版，避免后续无法区分绘图、计算和界面新增效果的开销。
