# 出生点预测同步与纯种子移植

2026-09-15：已移植原项目修正后的纯种子出生点预测，完整本地包无需连接游戏即可计算。设置中导入 `level.dat` 的存档记录继续优先于同种子估算。

## 实现

- 独立 `spawn-browser` 函数包保留已采集 RWG 的地形、`generateMapGen/rMapGen`、`rReplace` 和实际洞穴生成指令，包括火山地图生成和 BOP 多地表绘制器的调用顺序。
- 重放真实方块数组后执行洞穴。出生检查从 Y=63 向上读取连续非空气列，不能用群系默认方块或高度代替。生成过程只作用于独立内存数组。
- 原版规则接受草；BOP 接受沙或石头，雪层还需属于实际出生群系列表。当前只读采集确认：BOP provider、洞穴启用、MapGenCaves、空出生群系列表、wrapped-perlin 噪声。
- 保留 Java 48 位随机流及有界整数拒绝采样、64 位种子和逐运算 binary32。TeaVM 默认 `nextInt(bound)` 的归约方式不同，已对独立引擎中的原生调用映射到兼容实现；这会影响石头/圆石分布，不能忽略。
- 搜索从当前已核对 RWG 的空初始群系位置返回值开始，第 1000 次移动后立即终止，不额外测试终点。结果为 `ESTIMATED / POSSIBLE`，仅提供 X/Z，不把地表读取高度冒充实际出生 Y。

## 隔离与失败处理

首次请求出生点才加载独立引擎。最多缓存 64 个完整区块摘要（约 256 KiB）和 4 个种子搜索结果；内部群系坐标缓存也有上限。更换种子清理摘要，阶段失败或取消不写入不完整结果。模块加载失败可重试，区块之间让出执行权以处理取消。

原有地图与刷怪笼引擎、精算/粗算、线程调度和缓存没有改动。出生点使用既有 Worker 串行调用约定；导入存档的替换、取消与导出路径继续沿用原实现。没有新版完整函数包时，旧元数据仍返回无坐标的 `UNAVAILABLE`。

## 验证

- 520 项自动测试通过；新增加载重试、独立缓存、容量限制、数据校验、取消期间不缓存等检查。
- JVM 直接执行复制的原项目 `RwgChunkBiomeReplay.java` 与 `SpawnSearch.java`，以捕获的注册身份和原生生成类作为输入；仅适配无存档 World、注册表和兼容 Random。36 个区块、9,216 个洞穴后地表列与浏览器逐项一致。
- 6 个种子 × 原版/BOP 两种规则，共 12 个完整搜索的 X/Z、移动次数、是否找到可接受地表全部一致，包含有符号 long 极值和超过 JS 安全整数的种子。
- 原独立搜索终止测试另有 40 组 Java 对照，覆盖第 999/1000 步及初始随机消耗。
- 重放原有主世界密集/稀疏底图、村庄、其他结构、暮色和刷怪笼校准样本，零不一致；原四个优化引擎文件保持不变。

种子 `-8138049151491905853` 在当前 BOP 配置下自然计算到 `(-58,-180)`，移动 71 次，与原项目文档中已记录的出生点 X/Z 一致；没有硬编码该种子或坐标。本轮只读采集读取了配置与注册表，没有读取出生坐标、存档区块或生成区块。这里的一致性不等于所有实际存档均已验证。

## 精度边界与复测

纯种子结果仍是估算：未执行第三方 `ReplaceBiomeBlocks` 事件、结构、地物填充及后续存档修改。世界出生点、玩家床和首次进入时的随机站立点是不同概念；需要确认真实世界出生点时，仍可导入 `level.dat`。

编译：`tools/compile-spawn.py`，使用已有 RWG/cave 提取包与授权只读采集的 `spawn-runtime-profile.json`；独立输出到 `private-packs/spawn-browser`。更换 RWG/cave 类、噪声或气候组时必须重新审查及校准。

复测：`node tools/verify-spawn-sync.mjs`、`node tools/calibrate-spawn.mjs`、`node tools/validate-cpu-replacement.mjs`、`node --test tests/*.test.mjs`。校准报告记录源码、引擎、原生配置及参考结果哈希，过期报告阻止本地打包。未进行浏览器界面操作验收。
