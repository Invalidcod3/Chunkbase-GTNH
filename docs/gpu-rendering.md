# 可选 GPU 加速

设置面板提供「GPU 加速」和「计算并行度」两个独立滑条。GPU 档位决定哪些算法尝试在 GPU 上执行；并行度决定同时工作的独立计算线程上限，CPU 生成链也可以使用多个线程处理不同区域。两者均不降低地图精度，不表示显卡或处理器占用百分比。

## 使用与回退

| GPU 档位 | 作用 |
| --- | --- |
| 0 关闭 | 默认档，兼容绘图和 CPU 计算 |
| 1 轻量绘图 | 通过自检后使用 WebGL2 绘制 |
| 2 增强绘图 | 额外向浏览器请求高性能设备偏好，实际设备由浏览器决定 |
| 3 计算加速 | 加速矿井候选与末地群系范围；至少 1,024 个采样点或区块时尝试计算 |
| 4 扩展计算 | 增加主世界／下界史莱姆空岛与下界尖塔的随机判定；将计算门槛降低至 256 个采样点或区块 |

拖动时即时显示档位说明，松开滑条或键盘确认更改后才应用设置，避免拖动途中反复重建设备。旧 `off/auto/on/aggressive` 偏好分别保留为 0/1/2/3 档，4 档为 `maximum`，不会悄悄提高已有用户设置。已有缓存继续复用，小查询继续走 CPU。首次支持的查询触发后台初始化和自检，初始化期间查询先走 CPU，不等待设备就绪；通过后后续查询才使用 GPU，首次真实 GPU 查询仍做逐点核对。不能保证所有设备更快。

## 并行度

**1～4 档**分别请求对应数量的线程；**第 5 档是自定义**，输入范围 **1～64**。默认保持单线程，原有 1～4 线程偏好不变。自定义模式和输入值独立保存，即使自定义填写 2，也会在刷新后保留第 5 档。设置同时显示目标数量、当前上限、已就绪、启动中及等待回收的数量。

辅助线程按请求需要逐个启动，前一个线程的模块和函数包尚未初始化完成时不再增加新的线程。待执行任务保留在线程池的优先级队列中，每个就绪线程一次领取一个任务；线程就绪或任务结束都会继续调度，不依赖新的请求到来。已有线程空闲时直接复用，所有可用线程都有任务且仍有排队工作时才考虑扩张。辅助线程启动期间，已就绪线程可以继续处理剩余任务，不把短任务提前绑定给尚未启动的线程。每个线程都有自己的生成器实例、状态和缓存，同一线程内部继续串行处理查询。地图提交窗口也随就绪线程逐步增大，突破旧版最多 4 个待处理瓦片的限制，而非一次性排入几十个请求。

当前预算使用浏览器的 [逻辑处理器提示](https://html.spec.whatwg.org/multipage/workers.html#navigator.hardwareConcurrency)，预留一份处理能力；没有可用提示时保守使用 4。若 [设备内存提示](https://www.w3.org/TR/device-memory/) 不高于 2 GiB／4 GiB，分别限制为 2／4 个线程。这些值可能被浏览器简化，不是剩余内存测量，也不是系统允许创建线程数的精确上限；预算始终不超过目标数量和应用上限 64。

线程池还记录实际启动耗时和各维度、查询类型的近期耗时。对已经测过的工作，若现有线程预计会在新线程启动前处理完排队任务，就暂缓扩张；新类型仍允许逐步尝试。短批次结束后保留已就绪线程及其缓存，不因一次便宜查询自动清空。此策略控制启动是否值得，不是浏览器帧率、剩余内存或整机负载监测。

辅助线程创建抛错、启动超过 15 秒或线程运行异常时，停止扩张，并把预算降到仍健康的线程数量。主线程等待实际函数包就绪，不因加载超过辅助线程期限就被强行关闭；浏览器报告的主线程运行错误仍按失败处理。受影响的未取消查询转交健康线程；旧世界和已取消查询不会重试。失败限制保持到用户点击「重新尝试增加线程」，更改滑条不会造成反复创建失败。辅助线程启动超时会关闭线程，迟到的启动消息不能恢复它。所有线程均已失败时，地图「重试」也会先重建主线程，再重试函数包和地图；重建失败会返回错误，不再将空线程列表当作重试成功。浏览器若被系统整体终止，页面无法继续执行回退；当前机制处理的是应用能够收到的线程失败与超时。

提高并行度不重置主线程。降低并行度后，辅助线程先完成已经接收的查询，再释放其设备和线程缓存；新请求转向保留线程。主线程缓存与页面已完成的地图瓦片保留。切换世界和取消查询仍使用每个线程原有的 epoch/AbortSignal，迟到结果不会进入新世界。函数包重试会覆盖所有已加载线程；辅助线程故障可退回主线程，过期或已取消的查询不重试。

GPU 计算设置同时传递给所有线程，新线程继承当前档位；设备检查各自执行，部分设备不可用时显示部分线程回退。每个线程仍使用原缓存容量，但总内存、首次初始化成本和 GPU 设备开销会随线程数增加。并行度不是对 CPU 核心的强制占用，较高线程数不保证更快。

设置下方显示实际状态，不会仅凭选择框就声称启用成功。初始化、自检、纹理上传或绘制发生错误时，保留已完成样本，在同一次绘制中回退到兼容路径。GPU 绘图上下文丢失时回退；浏览器恢复后重新初始化和自检。另提供「重试 GPU 加速」按钮，避免不断自动重试异常设备。

选项以独立设备偏好保存，不写入整合包环境配置，不更改种子/维度视图偏好键，也不重置 Worker 或生成器缓存。关闭后释放 GPU 纹理和上下文；重新开启时从现有样本上传，不要求重新计算地形。

## 实现边界

使用 WebGL2 的 `R16UI` 整数纹理保存 `Uint16` 群系索引，256×256 RGBA 查色纹理覆盖全部 65,536 个索引。着色器用整数读取索引，再查配色；不会把群系 ID 当作颜色进行插值。平滑显示只在查色后混合相邻颜色。接口依据 [Khronos WebGL2 规范](https://registry.khronos.org/webgl/specs/latest/2.0/)。

世界坐标在 CPU 上转换成视口坐标后再传给 GPU，避免直接用着色器浮点数表示世界边缘坐标。裁剪瓦片只绘制有效采样矩形，沿用现有粗细瓦片覆盖顺序。鼠标群系查询仍读取原始数据。

GPU 绘制到独立画布，再合成到原有导出画布。资源、网格、结构、选中标记仍绘制在其上方，因此 PNG 继续从同一完整画布导出。GPU 开启时跳过新瓦片的 CPU 配色循环；回退时才按需补全兼容图像。改配色只更新查色纹理，不重新计算群系或上传全部样本。

GPU 样本纹理缓存限制为 32 MiB、最多 1,024 项，不包含屏幕缓冲区和驱动自身开销；失效瓦片及时释放。与 CPU 栅格缓存分别管理，不向原缓存写入 GPU 对象。

## 激进档计算范围

计算接口依据 [W3C WebGPU 规范](https://www.w3.org/TR/webgpu/)。计算发生在现有 Worker 内，使用独立的计算设备和 WGSL 计算管线；输出仍为普通整数数据，沿用原 Worker 群系命名空间映射、地图缓存、导出与取消机制。无需为 WebGPU 支持更改世界配置。WebGPU 不可用时自动使用 CPU，WebGL2 绘图可独立继续工作。

- **主世界矿井**：CPU 仅由世界种子生成两个固定系数；GPU 完成每个区块的种子组合、Java Random 48 位线性同余迭代、概率判断、`nextInt(80)` 拒绝采样与距离筛选。用三个 16 位整数分段保存低 48 位，正确处理负坐标、乘法溢出和完整 64 位世界种子。概率比较拆成 26＋27 位整数，不用 GPU 单精度近似 Java `double`。主世界 RWG 矿井列表和刷怪笼避让所需的矿井候选均复用此路径，其他结构保持原逻辑与原顺序。
- **末地底图**：岛屿位置和类型仍由原 Java Random/双精度 CPU 算法生成；GPU 根据区域索引并行判定中央岛、虚空和岛屿圆形范围并生成群系 ID。每座岛的圆形范围完全位于自己的 448 方块区域内，每个像素只需查一个区域。先检查局部范围再计算整数距离，世界边缘不会发生平方溢出。这仍是原项目的示意圆形群系底图。
- **史莱姆空岛／下界尖塔（4 档）**：CPU 提供 Forge 世界种子的两个固定系数；GPU 完成逐区块的 48 位乘加、异或、随机迭代、配置概率筛选与尖塔偏移。支持非二次幂的拒绝采样和二次幂分支；空岛和尖塔分别重置相同区块随机种子，保持原算法独立消耗随机数的语义。返回整数标志与偏移，CPU 按原边界裁剪并插入原结构位置，保留其他结构的生成顺序。
- **尚未接入**：暮色、RWG 地形/噪声、下界和其他多群系维度的 GenLayer、矿脉/流体算法及其他结构。激进档不会声称这些生成链已改为 GPU。

每个设备初始化时实际派发七组测试，覆盖负坐标、跨区域接缝、中央岛边界、世界边缘、正负 64 位极端种子，以及特意构造的 `nextInt(80)` 拒绝采样分支，逐项对照现有 CPU 实现。每种内核的第一条真实查询也进行全量对照。不同设备或重试后重新验证。这里只称为运行时一致性检查，并非对所有驱动和所有输入的数学证明。

4 档额外派发三组 Forge 测试，覆盖世界边缘、正负极端种子、概率为 1、二次幂概率、常规概率、高拒绝率和最大整数概率。旧档位不会运行新的 Forge 计算管线。

设备丢失、编译失败、异常输出、GPU 错误或等待超时后丢弃计算结果，当前查询回退原 CPU 路径；后续查询停止申请设备，直到用户重试。改变档位立即释放计算设备，旧任务结果不会作为新设备结果返回；世界切换仍用原 Worker 的 epoch 和取消信号隔离。最多 262,144 个输出、65,536 个末地区域；每次派发的应用缓冲区合计不超过约 3 MiB，完成或失败后释放，不改变已有生成器缓存容量。

## 验证与限制

每次启用或恢复上下文时，实际运行同一着色器绘制 2×2 测试图，再读取像素，检查索引 1、256、4096、65535 的配色及上下方向。自检不通过不会启用。

自动化测试覆盖设置保存、不可用/编译失败/自检失败、整数纹理上传与奇数行对齐、高 DPI 视口、纹理复用与容量淘汰、配色更新、丢失/恢复/重试、同帧 CPU 回退、保留样本、覆盖层顺序及原导出画布。测试中的 WebGL API 使用替身，不能代替实际驱动测试；实际像素自检由用户设备在启用时执行。

计算自动化测试另以整数解释器对照原 CPU 算法，覆盖 225 组末地查询和 30 组矿井查询，并检查设备不可用、编译/映射/验证/数值失败、设备丢失、重试、取消、切换档位和首条真实查询不一致的回退。API 替身用于生命周期检查，不能代替实际驱动执行 WGSL；实际 GPU 自检在用户启用时运行。

本轮增加 120 组 Forge 输入对照，以及滑条偏好迁移、按需分配、线程收缩、全部线程取消、部分 GPU 回退和辅助线程故障测试。另用 Node 的真实独立工作线程运行同一 Worker 模块，验证四个独立生成环境的群系结果和切换世界后的输出。这些测试不等于浏览器里的实际吞吐量基准。

加入自定义与容量退让后，全部 483 项自动化测试通过，新增覆盖设备预算、超过四线程分配、启动串行化、创建失败、启动超时、失效线程回收与状态、停止扩张及手动重试、全部线程失效后的恢复、偏好恢复、输入校验与瓦片窗口联动。完整私有预览另通过八个真实独立工作线程进行六个维度的 9 次查询，2,907 个群系像素与单线程参考一致。此对照使用 Node 线程；浏览器里的启动失败和资源不足路径通过替身模拟，未进行真实浏览器资源耗尽测试。此前已保存的实例参考校准保持有效：916 个结构结果、99 个刷怪笼候选、2,293,760 个洞穴单元，以及末地小行星选择/避让检查。本轮未更改这些生成算法。

本轮未执行浏览器截图、真实 GPU 性能基准或实际 PNG 文件视觉验收。Canvas 2D 也可能由浏览器内部加速；增加绘图/计算通道不保证所有设备更快，数据回读和首次验证也有开销。暮色、罗斯128b和漆黑世界生成算法仍在 CPU 上执行；并行度增加可让不同区域同时计算，单块算法本身尚未迁移至 GPU。
