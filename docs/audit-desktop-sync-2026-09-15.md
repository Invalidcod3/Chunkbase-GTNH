## 后续功能开发顺序

1. **从指定坐标查找最近 N 个结构或资源。** 原项目已有 `RadialCoordinateLocator`，按区域到起点的最小距离扩展，只在更近区域完成扫描后确认结果，并处理等距、预算和取消。Web 已有自定义矩形范围、数量上限、进度和取消，但仍按区域扫描截取，不能保证最近 N 个。适合在 B1/B2 后优先补齐；应复用查询接口，不重写底图缓存。
2. **跨会话保留已计算底图。** 原项目新源码增加 `MapStorage` 的磁盘缓存（容量上限、校验、原子写入）和 `MapCacheIdentity`。Web 已有内存瓦片/区块/栅格缓存及偏好保存，缺少刷新或重开后的底图复用。可新增独立 IndexedDB 适配层，缓存原始群系数据，以生成器/配置哈希、种子、维度和采样方式隔离；配色更新只重绘，避免不必要重算。必须包含容量回收、版本迁移和坏数据回退。桌面新实现本身尚未在本轮做运行验证。
3. **单点路标及更完整的 JourneyMap 导出。** 原项目已有点击结构/资源生成路标、后台自动导入、去重、结构高度或矿脉中间高度以及对应颜色。Web 现有详情、复制坐标和批量 ZIP，可先补单点导出、收藏和可选自动 Y/颜色；现有手工 Y 已注明不是实测地形高度，不能当作高度算法错误。直接写入游戏需要另行开发本地连接服务。
4. **按种子和维度保存视图历史，统一早期群系元数据。** Web 已保存最近视图、筛选和自定义配色，但尚未形成多种子视图历史。早期月球、火星等内置群系别名也可迁移到与新环境包一致的注册元数据；应保留旧设置迁移，不能仅改键后丢掉用户配色。
5. **独立规划游戏/存档能力。** 已生成区块、玩家位置、实际勘探记录，以及新 Worker 的存档相关缓存身份，均与静态预测包的架构不同。属于可选产品扩展，不应为了追齐桌面菜单塞入此次显示修复。

本轮没有发现相对于核对范围新增遗漏的维度或结构类型。完整包仍包含 **42 个底图、41 个资源维度、63 个配置资源图层**。小行星带三类基地仍是原项目的兼容逻辑起点，当前 1.7.10 整合包没有对应实际生成器；保留提示，不把它们当作已证实建筑。废土世界在当前采集实例中只有一个允许群系，固定底图有采集依据；未来配置变为多群系时需要新适配和校准。
