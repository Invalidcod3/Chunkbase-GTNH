# 暮色与扩展维度加载优化 · 2026-09-15

本轮优化暮色森林、下界、木卫一、冥王星、巴纳德C、罗斯128b、漆黑世界的底图计算。保留现有主世界优化、Worker 串行调度、结构/资源模块、页面瓦片缓存与粗算→精算流程。GPU 属于下一步，不在本轮启用。

## 实现

- **按耗时安排暂停。** 以前暮色和扩展维度每算完一小批就等待一次定时器，现在累计约 16 ms 后让出线程。批次仍有尺寸上限，每批检查取消；短任务也会在完成前让出一次，以接收已排队的取消。16 ms 是检查预算，不是任何设备上都能保证的单次耗时上限；同步生成器调用不能中途抢占。
- **暮色增加有限批量。** 直接查询由每批 16 行增加到 32 行；抽样路径的源矩形高度由约 32 增至 64，减少重复执行父群系层。保留 1:4 群系图与完整分辨率的区别，输出坐标不变。
- **完成栅格缓存。** 暮色和扩展提供器各自新增最多 8 MiB、256 项的内存缓存。缓存身份覆盖种子、维度和采样语义；每个提供器绑定自己的固定配置与目录。旧结果按最近使用顺序淘汰。
- **精细结果服务粗采样。** 对齐且被已完成精细结果覆盖的请求直接抽取对应样本，不插值，不把粗预览当作精算结果。当前实现不复用粗算内部的 GenLayer 中间数组，因此首次粗算加精算仍可能重复部分工作。
- **响应与缓存分离。** 缓存保存群系索引而非颜色，返回独立数组；转移响应缓冲区或重着色不会破坏缓存。失败、取消及不完整结果不写入完成缓存。可通过提供器选项 `rasterCacheBytes: 0` 关闭新增缓存。

固定群系维度继续直接填充数组，未为它们增加无收益的复杂生成流程。原有 RWG 区块/栅格缓存、资源缓存及失败恢复逻辑未修改。

## 本机对照结果

同一编译引擎，优化前后适配器配对运行；种子 0、1、2，起点 (-512,1024)，128×128 像素；三次中位数，交替执行顺序。不同采样间隔覆盖的世界面积不同。下表是 Node 本地计算时间，**不是浏览器首屏时间，也不是与 Java 客户端的速度比**。

| 维度 | 间隔 4：优化前 → 后 | 间隔 16：优化前 → 后 | 首次计算提速范围 |
| --- | ---: | ---: | ---: |
| 暮色森林 | 107.69 → 29.66 ms | 979.95 → 261.32 ms | 3.17–3.75×，含间隔 8 |
| 下界 | 229.06 → 96.90 ms | 3770.63 → 947.65 ms | 2.36–3.98× |
| 木卫一 | 230.31 → 76.89 ms | 3867.55 → 941.72 ms | 3.00–4.11× |
| 冥王星 | 215.80 → 77.60 ms | 3885.79 → 922.59 ms | 2.78–4.21× |
| 巴纳德C | 231.03 → 75.91 ms | 3859.21 → 907.62 ms | 3.04–4.25× |
| 罗斯128b | 492.33 → 492.16 ms | 5868.47 → 4923.42 ms | 1.00–1.19× |
| 漆黑世界 | 492.44 → 468.02 ms | 4696.00 → 4178.58 ms | 1.05–1.12× |

暮色间隔 8 为 247.40 → 77.98 ms。重复请求在新增缓存命中时为 0.04–0.12 ms，仅包含返回样本，不包含 Worker 通信与绘制。不能把缓存命中速度当作首次计算速度。

这些样本在优化前后逐像素一致。测量后还修复了下述极端种子的群系别名问题；它未在性能表的三个种子/区域中触发。性能原始记录保留对应代码哈希，位于 `.test-work/dimension-loading-benchmark.json`。复现工具为 `tools/benchmark-dimension-loading.mjs <优化前适配器目录>`，本次基线保存在 `.test-work/dimension-performance-before/`；这些本地基线不包含在源码 ZIP 内。

## 回归过程中修复的既有问题

种子 `9223372036854775807`，范围起点 (-517,-1031)、19×35、间隔 128，在罗斯128b和漆黑世界遇到注册槽位 **161**。旧适配器直接使用槽位作为群系 ID，而当前实例实际返回 **160**，导致目录查找失败；罗斯128b加上显示偏移后表现为找不到 6561。

已向明确选定的 GTNH 2.9.0-beta-3 实例做两次只读查询，协议 21，共 1,330 个像素。罗斯128b在 (251,3065)、(379,3065) 实际返回 6560；漆黑世界返回 160。现在在维度替换和显示偏移前应用已校准别名，不增加虚构群系或随意填色。

映射记录在 `tools/space-biome-aliases.json`，与采集的生成器配置 SHA-256 绑定。准备其他配置时需重新核对；不是对所有整合包硬编码 161→160。两份实机参考记录加入额外维度校准报告，并在安装后验证这两个位置。

## 验证与后续

- Node 回归覆盖缓存缓冲区转移、独立副本、容量淘汰、种子/维度/采样语义隔离、细到粗复用、取消和失败后重试、别名先于维度偏移等行为。
- 已保存的暮色实机参考：76,800 像素、3,845 个特征；扩展维度参考加新增别名案例：116,530 像素、7,182 个结构。逐项校准，不修改旧参考结果。
- `verify-dimension-optimization.mjs` 使用真实编译引擎，对比旧/新适配器的负坐标、64 位种子、间隔 1–256、拆分与细到粗缓存。旧适配器仅对已实机验证的 161→160 别名归一化；新适配器使用实际目录，不能以补全虚构目录掩盖加载失败。
- 完整本地包重建后继续检查 42 个底图、41 个资源维度、63 个资源图层，以及原有 RWG 和最新汉化、冥王星配色。

罗斯128b和漆黑世界的首次加载仍受生成器计算限制，提升较小。本轮没有移植 WASM、多 Worker、持久化缓存或 GPU；没有执行浏览器视觉/交互性能验收。下一步 GPU 设计应据此区分计算、调度和绘制成本，并保留精确 CPU 路径与统一的缓存数据格式。
