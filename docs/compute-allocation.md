# 算力分配：速度与观感

设置中的“计算并行度”下方新增“算力分配”滑条，范围 0～100，默认最左侧 0（速度优先），偏好单独保存在 `amidst-compute-allocation-v1`。拖动即时影响后续调度，松开后保存；不修改线程总数、GPU 档位或世界配置。

这版“观感”指优先把已有粗预览精化为原有完整瓦片。它改变清晰瓦片出现的顺序，所有档位的最终采样精度一致，不使用插值替代生成结果，也不新增超分辨率计算。

## 分配规则

若当前可用且就绪线程为 N、滑条比例为 P，则预留精化线程数为 `min(N - 1, round(N * P / 100))`，至少保留一个线程出图。设置界面显示按当前就绪容量换算的线程数，而非将滑条百分比当成真实 CPU 占用率或耗时比例。

| 滑条位置 | 4 个线程：出图 / 精化 | 8 个线程：出图 / 精化 |
| --- | --- | --- |
| 最左 0 | 4 / 0 | 8 / 0 |
| 25 | 3 / 1 | 6 / 2 |
| 中间 50 | 2 / 2 | 4 / 4 |
| 75 | 1 / 3 | 2 / 6 |
| 最右 100 | 1 / 3 | 1 / 7 |

- 同时有两类任务时，按比例调度；一类没有任务时，另一类借用全部空闲容量。因此 0 档也会在原有流程中完成精化，不会永久停留在粗预览。
- 单线程优先出图再精化；设备退让、线程启动和回收后按新的就绪数量重新换算。
- 比例调整不打断正在执行的查询，不重启线程，不清空缓存。已有查询完成后逐步达到新分配；借用中的线程也在查询完成后归还。
- 保留逐步启动、启动成本判断、失败回退和空闲一分钟回收额外线程的机制；分配不会突破用户设置和设备限制。
- 暮色、下界等直接生成完整瓦片的维度没有独立粗预览精化阶段，全部线程仍可参与出图。不会为制造“观感工作”而恢复低收益的重复粗算。
- 结构、资源和导出任务维持原有任务优先级，在非精化侧正常调度；各类内部仍保留已有优先级和视野中心顺序。

地图请求端与线程池使用同一分配函数：前者避免所有待办位置被新预览占满，后者在实际空闲线程上按类别选择任务。仅在一个位置调整队列，无法稳定保证混合任务下的比例，所以两端均接入分类。

## 验证

506 项自动化测试通过。新增覆盖 1～64 个线程、0～100 比例的整数分配、默认值和保存、单线程退让、混合队列的 2/2 与 1/3 分配、实时调整、不取消已有任务、无精化时借用全部线程，以及视野尚有空白时提前完成完整瓦片。既有内存预算、缓存复用、世界切换与 GPU 回退测试继续通过。

完整私有预览在 50 和 100 两档各通过一次 8 个真实独立计算线程与单线程输出对照：每档 6 个维度、9 次查询、2,907 个像素无差异。可用 `node tools/verify-parallel-preview.mjs --eight --allocation=50` 复测，将参数改为 `--allocation=100` 验证最右档。该测试用于结果一致性，不能替代实际浏览器观感和吞吐量测试。
